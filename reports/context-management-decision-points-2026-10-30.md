# 从 property 到具体 context 管理决策点

日期：2026-10-30。[分析入口](README.md) · [DAB 六任务映射](dab-six-case-mapping-2026-10-30.md) · [跨应用共同模型](unified-object-trace-analysis-2026-10-30.md)

**本报告补齐“条件 → 具体节点 → 保留 / 移出内容 → 原轨迹中的后续使用 → 反例”这一步。** 给出四类应用的四个管理候选和两个条件不成立的对照。全部来自已有记录；候选 context 是分析阶段构造的示例，未用于任务 agent 续跑，也没有执行轨迹中的工具。

这里的 Full-history 仅作明确的比较定义：把节点前的来源消息依序放入参考历史。各来源没有统一的逐次 API 输入快照，因此不能声称原模型当时确实收到了这些全部内容，也不能报告实际 token 节省。系统规则、工具接口和完整用户任务在各候选中继续保留；下面重点展示工具观察如何管理。

## 2. C1：大结果已取得、计算仍未完成，怎样管理

来源：[D5 完整步骤](../samples/data-analysis/05-evening-businesses/README.md#step-7) · [逐调用映射](../samples/data-analysis/05-evening-businesses/mapping.md) · [原始 JSON](../samples/data-analysis/05-evening-businesses/trace.raw.json)。

**原始 Task：**工作日至少一天 18 点后仍营业，按平均评分取 top 5，必须包含名称、营业时间和平均评分。

节点前已发生：S3/S4 查询到 79 家商户、2,000 条评论；S5/S6 返回两份大结果的预览及存储键；S7 把存储键拼成文件名，执行在第一次 open 时 FileNotFoundError，尚未完成解析和计算。因此这个节点区别于“只剩最后作答”的节点。

### Full-history 参考与候选管理

| 内容 | Full-history 参考中有什么 | 候选如何承接 |
|---|---|---|
| 原任务与工具协议 | 全部来源规则和查询要求 | 继续保留，尤其“存储变量值可能是实际文件路径”的协议 |
| 商户结果 | S5 的长预览及存储键 | 保留 gmap_id/name/hours、表示说明及真实存储键；旧预览可候选外移到日志 |
| 评论结果 | S6 的长预览及存储键 | 保留 gmap_id/rating、数值转换说明及真实存储键；计算仍需读完整评论 |
| 样例与格式 | S1/S2 和大结果预览中已出现的表示 | 保留 hours 为 JSON 编码字符串或 "None"、rating 为数值字符串等已知情况；样例不保证覆盖全部格式 |
| 最近失败 | S7 错误文件名和 FileNotFoundError | 保留具体失败与正确接口约束，避免将句柄误当路径；最新反馈不先丢弃 |
| 计算产物 | 此时尚未产生 top 5 | 不提前写入 S8/S9 的名称、排名或平均评分 |

候选变化部分可写为如下说明（分析示例，非已运行日志；实际实现还需保留原任务、系统及工具定义）：

```text
阶段：两份大结果已经返回，计算尚未完成。
Task：至少一个工作日 18:00 后仍营业，按平均评分取前 5，输出 name、hours、avg_rating。

商户结果：gmap_id、name、hours；记录中的总体计数为 79。
恢复入口：locals()['var_function-call-11402182038532519728'] 的值。
hours 可为 JSON 编码字符串，也出现字符串 "None"；不能用少量样例替代完整 hours 数据。

评论结果：gmap_id、rating；记录中的总体计数为 2000。
恢复入口：locals()['var_function-call-14327882022513570432'] 的值。
rating 以字符串返回；按 gmap_id 关联并使用完整评论计算。

最近一次尝试失败：open('var_function-call-11402182038532519728.json') → FileNotFoundError。
存储键不是文件名，不能自行追加 .json；按原工具协议读取变量中的实际值。
保留最新错误原文和已见格式样例，完整结果须在存储中继续可达。
```

**后续事实：**S8 原代码从两个 locals 存储项取得实际路径并打开，完成聚合与营业时间处理，产出含 name/hours/avg_rating 的 top 5；S9 作答。这证明原环境当时支持正确的恢复操作，不证明压缩后的 agent 会选对操作，也不证明时间解析或答案正确。

**候选成立的条件：**两份完整结果仍可达；恢复协议和已知格式保留；模型需要时能实际读取全量；不能只拿预览或前 5 行计算。若无法确认某条新观察此前已被展现，实际实现应先保留该最新观察，而非立即缩减。这里只分析恢复与后续用途，未核验原请求的精确输入。

外部 JSON 文件没有随原轨迹归档发布，仓库中的完整消息不能直接当作可运行 checkpoint。S8 后另有“产物交接”候选，但只能保留 name/hours/avg_rating 全部要求字段，不能用只有名称的列表替代。

## 3. C2：Coding 的最新局部源码，能否承接较早的大范围观察

来源：[S22 最新函数](../samples/software-repair/01-posix-path/README.md#step-22) · [S23 编辑与后续验证](../samples/software-repair/01-posix-path/README.md#step-23)。

- **节点状态：**正在修复 GetEdk2RelativePathFromAbsolutePath；S20 已记录 Windows 风格分隔符在 POSIX 环境下产生错误结果。S22 已取得 `path_utilities.py` 第 173–222 行，尚未执行 S23 编辑。
- **保留：**原任务约束；S20 的 input/expected/actual 及退出码 1；S22 最新完整函数片段；复现脚本位置；当前为编辑前状态。真实源码版本哈希没有记录，不能补造。
- **候选外移：**S10 的广范围源码和 S12 的广范围测试文件观察，以及早期目录/帮助输出，转为文件路径、范围、用途和可恢复引用。不要把源码本身从工作目录删除。
- **下一步实际使用：**S23 编辑的 old_str 位于保留函数片段内，S24 重跑同一脚本，来源输出转为成功。这给出了“当前明确操作所需片段”的依据。
- **条件与反例：**其他源码可能仍有后续用途，因此需要可达的文件和正确状态；S23 修改后，旧源码观察和 S20 测试结论不能继续当作新版本事实。S20/S24 同命令产生不同结果，正是“重复调用可直接省略”的反例。

这里可迁移的是“最新局部观察＋对象状态＋恢复入口承接旧广范围观察”的候选方式。SQL 结果与源码的具体检查规则不同；当前片段覆盖下一次 old_str，不等于覆盖模型所有潜在推理需求。

## 4. C3：QA 的局部证据与引用，怎样承接旧文档窗口

来源：[法老排序 S6/S7](../samples/research-qa/01-pharaoh-order/README.md#step-7) · [同一文档后续读取 S21](../samples/research-qa/01-pharaoh-order/README.md#step-21)。

选择 **S7 find 返回后**，保留最新 find 观察；较早 S6 的文档窗口才作为候选外移对象，不先丢刚返回的匹配结果。

| 保留的状态 | 候选外移的内容 | 恢复与后续事实 |
|---|---|---|
| 四条完整人物线索及年代排序要求；已见事实和行号；URL、Doc 5、cursor=4 映射；最新 S7 匹配结果 | 较早搜索列表及 S6 展示窗口中暂未直接使用的正文；保留其来源、范围和可重取引用 | S7 用 `find(cursor=4, pattern="beaut")`，后续 open/find 多次用该 cursor 按位置读取；最终引用使用后来返回的 18/19 等新 cursor，映射需继续保留 |

该文档记录长度是 294 行，S6 只显示 L0–L44，不能说 agent 已获得全文。没有读取的部分不属于“从历史中删除”的内容。已有文档内定位能力支持引用式候选，但 cursor 跨会话寿命、版本一致性，以及删掉旧窗口后模型是否仍会正确定位，都未验证。

**反例 N1：**[足球问答 S6](../samples/research-qa/03-football-finalist/steps-01.md#step-6)的 Excel 路径交给 browser.open 后 corpus 404。此时必须保留“工具访问失败、表格内容尚未取得”，不能将路径当成已有数据的可恢复 handle。后续 S44 再次失败是审计证据，不提前放入 S6 的候选上下文。

## 5. C4：Web 用已完成行动的检查点承接旧表单

来源：[发帖 S5/S6](../samples/browser/01-relationship-post/README.md#step-5)。按动作前观察对齐：S5 是点击提交；S6 的 observation 才显示新帖子页面，之后才执行 S6 的输入动作。

建议候选状态包括：

```text
原始目标保持不变。
已观察到提交结果：帖子题为 Advice on cheating in a relationship，forum 为 relationship_advice。
当前帖子路径：/f/relationship_advice/2/advice-on-cheating-in-a-relationship。
已发生一次 Create submission；它是写入副作用，不应为恢复历史而重放。
保留 S6 当前页面完整观察，包括 Comment 控件 [7801] 和当前可见状态。
旧搜索页、标题输入 [5225]、forum [5790]、提交 [5680] 的完整视图可候选转为上述检查点。
```

下一动作确实使用新帖子上的 Comment，而非旧表单控件。候选要求已取得提交成功后的可见状态，并保留原任务、已写入内容和完成事件；不能只有一个“done”标记。当前帖子 URL 可以定位对象，但不能单凭 URL 恢复旧表单的已填状态；精确旧观察需另有快照或原始日志。重复点击提交也不是等价的读取操作。

与 D5 的共同点是阶段改变后可考虑用新状态承接旧观察；区别是 Web 含外部写入副作用，恢复不能重放动作。当前页面仍可能遗漏隐藏状态，因此这里同样不是安全性保证。

## 6. N2：Data Agent 中不能随意“把大结果变成一个平均数”

来源：[D6 聚合过程](../samples/data-analysis/06-indianapolis-ratings/README.md#step-4) · [对象与引用映射](../samples/data-analysis/06-indianapolis-ratings/mapping.md)。

在 S5 后、S6 前，历史已有：

- S4：匹配评论逐条参与 AVG，结果为 3.86046511627907。
- S5：按商户得到各自 AVG 的列表及其分组口径；此时还没有 S6 的再平均结果。

节点后的审计事实是：S6 才将这些商户均值等权平均，得到 3.977777777777778。这个数值不能提前写入 S6 之前的候选 context。

这两者的统计单位和权重不同。候选摘要必须标注各值对应的筛选集合、分组和口径，不能写成一个无来源的“平均评分≈3.9”。如果后续需要重新合并分组，还可能需要 count/sum 或完整结果；当前没有的计数不能生成出来当作来源数据。

这是聚合语义的边界，不是本报告对任务答案的重新评测。它与 Coding 的版本边界、Web 的写入边界一样，都说明“更短的表示”要有具体承接条件。

## 7. 从决策点归纳三个可讨论的 property

| 候选 property / 条件 | 具体管理动作 | 跨应用证据 | 条件不满足时 |
|---|---|---|---|
| **局部承接：**最新局部证据覆盖当前明确操作，旧广范围观察仍有定位/状态信息 | 保留局部证据及引用，候选外移较早广范围正文 | C2 当前函数支撑编辑；C3 最新匹配结果支撑继续定位；D5 计算后必须保留完整所需字段 | 未排除未来依赖时不能宣称其余信息永久无用；D6 不同聚合口径不能无标签合并 |
| **可恢复引用：**已有访问入口、正确工具协议、必要表示信息和可达存储 | 用表示说明＋真实引用承接旧长观察，需要时实际恢复 | C1 两文件通过 locals 读取；C3 文档通过 cursor/open/find 定位 | N1 Excel 路径不可达；C1 错拼文件名也失败。未证明恢复便宜或跨会话可用 |
| **阶段检查点：**前一阶段有可见产物，新状态已经取得，尚需保留的用途明确 | 用产物/完成事件＋新状态承接旧探索与交互视图 | C4 提交后帖子状态；D3/D5 计算后完整名单或 top-5 结果 | 保留写入副作用，禁止以重放提交恢复；最终作答节点不能替代计算前验证 |

三条目前都是**由真实步骤支持的管理假设**。已给出具体节点、保留/移出对象、原轨迹后续行为、恢复入口及边界；尚未得到压缩后的操作选择、恢复行为、正确率或净成本结果。进一步实验应从同一节点分别继续 Full 与候选 context，不能把本报告的静态分析包装成已经运行的实验。
