# 从对象性质到跨应用的 trace 模型

日期：2026-10-30。材料仍为四类应用各 3 条正文轨迹及 3 条 FreeInference 元数据会话；[全部样本、原始任务与逐条证据索引](cross-application-properties-2026-10-29.md)。本次只重新组织已有证据，没有新增数据、模型调用或实验。

**核心判断：可以统一建模的是“观察与相关状态的绑定、信息的后续依赖、恢复的条件”；应用之间不同的是这些条件的具体检查方法及代价。** 对象性质是重要依据，但需要与对象表示、工具操作和任务需求一起分析。可复用、稳定、重取昂贵都不宜直接归为某种 agent 的固有性质。

## 1. 先修正分析单位：application 不是对象类型

| 已有具体记录 | 对原判断的修正 |
|---|---|
| [D1：亚洲股指，步骤 5→6](../samples/data-analysis/01-asian-index/README.md#step-5)：SQL 大结果物化为 JSON 文件；Python 通过存储键取得路径，`open`、`json.load` 后构造 DataFrame，再解析和聚合。 | 同一 Data Agent 同时面对数据库、结果文件及派生表。重新查询数据库与读取已物化结果是不同恢复操作，代价不能混算。 |
| [S2：NetCDF 名称修复，步骤 72→79](../samples/software-repair/02-netcdf-variable-names/README.md#step-72)：修改源码的名称清理函数；测试读取 SDF 数据集，确认字段名变化，再尝试写 NetCDF，遇到属性 TypeError。 | Coding 任务也包含结构化数据和格式转换；需要分别记录源码状态、数据表示和输出约束。不能把整条轨迹只标成“代码对象”。 |
| [W3：项目推广，步骤 9→10](../samples/browser/03-promote-repository/README.md#step-9)：浏览器取得 GitLab 的 AndroidAsync 项目页。 | “代码项目”在这里以网页表示被访问；未观察到源码读取或编辑。对象身份、当前表示和可用操作要区分。 |
| [Q3：足球问答，步骤 6、44](../samples/research-qa/03-football-finalist/steps-01.md#step-6)：任务给出 Excel 路径，但 `browser.open` 两次返回 corpus 404。 | 问答任务也可能涉及表格文件，但涉及该对象不等于工具能访问它；不能据路径判断已取得数据。 |

因此，建议以**某个对象的具体表示，在相关状态下被执行的一次操作及其观察**作为基本分析单位；application 保留为任务背景。这是当前证据支持的建模选择，尚不是“足以决定所有行为”的结论。

还需区分三个层次：

| 状态层次 | 例子 | 对 trace 管理的含义 |
|---|---|---|
| 外部对象状态 | 源码内容、数据表内容、已保存结果 | 影响旧观察是否仍适用；一次测试可能依赖多个文件及执行环境。 |
| 交互状态 | 当前 tab、表单值、可见页面与会话状态 | 同一 URL 不一定对应同一可操作界面。 |
| 模型 context 状态 | 保留了哪些观察、摘要如何组织、前缀在哪里被改写 | 即使没有观察到外部对象更新，历史追加、裁剪和重排也会改变输入与缓存复用。 |

任务要求和 agent 的选择策略同样影响轨迹，不能仅由第一层推导第三层。

## 2. 哪些可以统一建模：三个共同的判定问题

统一记录一条历史观察时，可包含五项：**对象标识、当前表示及已知相关状态；操作与参数；观察内容；已知后续引用；恢复条件**。一个操作可以涉及多个对象。状态或依赖不清楚时保留“未知”，不默认稳定或已失活。这是分析表示，不是新增运行框架。

### 共性一：旧观察的有效性依赖相关状态与操作条件

共同问题是：**旧观察是否仍能回答当前这次操作需要知道的事？** 检查内容因对象而异，但判定问题可以共享。

| 应用 | 已有证据 | 可统一的部分 / 当前边界 |
|---|---|---|
| 数据分析 | [D1 步骤 5→6](../samples/data-analysis/01-asian-index/README.md#step-5)直接读取已物化结果，而非再次执行 SQL。 | 可绑定到具体结果对象；但轨迹未记录源数据库更新过程，不能据此证明长期快照有效。 |
| Coding | [S1 步骤 20→24](../samples/software-repair/01-posix-path/README.md#step-20)：同一 `python reproduce_issue.py`，源码修改前失败、修改后通过。 | 命令相同不足以复用结果，需关联源码和环境状态；复测是获取新证据。 |
| Web | [W1 步骤 3→4](../samples/browser/01-relationship-post/README.md#step-3)：同一 `/submit` URL，标题从空变成已填；随后选择 forum。 | 页面地址不是完整状态，观察需绑定当前交互状态。 |
| 检索问答 | [Q2 步骤 3→24](../samples/research-qa/02-image-personalization/README.md#step-24)：同一摘要的 L0–L25 内容相同，但 cursor 从 1 变为 21。 | 内容、来源和引用标识可分别记录；两次相同不能证明文档永久稳定。 |

**共性是有条件的有效性，不是“所有对象都稳定”。** 对象版本一致也可能仍不够：时间、随机性、外部服务和未记录环境都可能影响结果；现有轨迹未完整暴露这些条件。

### 共性二：信息有跨步骤依赖，年龄和重复次数不足以判断用途结束

| 应用 | 已有证据 | 可统一的部分 / 当前边界 |
|---|---|---|
| 数据分析 | [D2 步骤 3→11](../samples/data-analysis/02-trading-volume/README.md#step-11)：旧公司描述在多步后以 `stock_info` 读回，与均值结果结合；[D3 步骤 3→5](../samples/data-analysis/03-perfect-rated-books/README.md#step-3)将两组查询结果匹配成名单。 | 可记录结果到后续计算、再到回答的显式引用链。旧结果未因经过若干步而自动无用。 |
| Coding | [S1 步骤 20→24](../samples/software-repair/01-posix-path/README.md#step-20)中的具体失败输入、局部源码修改和复测相互关联。 | 可关联失败案例、修改对象和验证证据；这种行为关联不等于已恢复完整语义依赖图。 |
| Web | [W1 步骤 5→6](../samples/browser/01-relationship-post/README.md#step-5)：Create submission 后进入新帖子，下一动作使用新观察中的 Comment 控件。 | 观察中的对象/控件引用支撑后续动作；导航后需要新的动作依据。不能仅从输出一个控件 ID 推断其他页面信息均可删除。 |
| 检索问答 | [Q1 步骤 6→21、23](../samples/research-qa/01-pharaoh-order/README.md#step-21)：旧文档 cursor 再次定位局部行，最终回答引用行号提取人物事实。 | 文档、段落和回答间可追踪引用；文档较早取得不等于不再需要。 |

重复也应按这个关系解释：[W2 步骤 11→12](../samples/browser/02-repost-eagle/README.md#step-11)的点击与可见观察完全相同，未见推进；S1 同命令复测却验证了新代码状态。它们不能用同一种“重复次数”直接判为冗余。

**可以统一记录“谁还引用了什么”；不能直接由记录推出“未引用部分都可删”。** 存储键、cursor、控件 ID 是显式引用，因果推理和未来需求则可能没有完整记录。把原始数据替换为派生结果，仍需确认该结果覆盖被允许的后续用途。

### 共性三：可定位、可恢复、可低成本恢复是三个不同条件

| 应用 | 已有证据 | 可统一的部分 / 当前边界 |
|---|---|---|
| 数据分析 | [D1 步骤 5→6](../samples/data-analysis/01-asian-index/README.md#step-5)：存储键确实被用于打开完整结果文件。 | 给出当次恢复成功的正例；不能由此推断重新执行 SQL 与读文件同价，也不证明文件跨会话保存。 |
| Coding | [S2 步骤 64→69](../samples/software-repair/02-netcdf-variable-names/README.md#step-64)通过 stash/pop 恢复 tracked 改动；[S3 步骤 67](../samples/software-repair/03-androidtv-adb/README.md#step-67)删除临时验证脚本。 | 恢复依赖版本和产物生命周期，单独保存路径不足以保证恢复旧内容。 |
| Web | [W1 步骤 3→4](../samples/browser/01-relationship-post/README.md#step-3)中 URL 不变但表单状态变化。 | 再访问 URL 不自动恢复此前已填内容或当前可见控件；这里未进行页面恢复实验。 |
| 检索问答 | [Q2 步骤 25](../samples/research-qa/02-image-personalization/README.md#step-25)的 PDF 404；[Q3 步骤 6、44](../samples/research-qa/03-football-finalist/steps-01.md#step-6)的 Excel 路径无法通过所用工具读取。 | 恢复受工具能力与资源可达性约束；失败不证明文件不存在，摘要可取也不证明全文可取。 |

**可以统一记录恢复入口；可达性与内容一致性标注已证实、失败或未知，恢复代价记录测量值、界限或未知。** handle、URL 或文件路径是模型中的定位字段，不是无条件省略正文的凭据。恢复操作还必须可被后续 agent 正确调用，且不引入不允许的副作用。

## 3. 哪些需要专用机制：差别在“怎样检查”，不在“是否有这个问题”

| 对象 / 任务类型 | 需要专门处理的语义 | 统一模型中对应什么 | 不能据此泛化的说法 |
|---|---|---|---|
| 数据库结果及表格计算 | SQL 的筛选、连接、聚合；行列依赖、类型、日期格式、空值；结果与源快照的关联。D1 日期样例未覆盖全表，D3 有 ID 匹配步骤。 | 有效性、后续用途与恢复条件的检查方法；可尝试利用关系算子及 provenance，但本次未实现或证明。 | “DB 总是昂贵且稳定”“前几行足以代表全量计算需求”。 |
| 源码、工作树与程序执行 | 文件/函数位置、patch、构建环境、测试输入与结果的依赖。 | 对象状态和验证依赖；稳定的未改文件也可能复用，变更后的测试则需重新判断。 | “Coding 都是持续写入，所以不可复用”或“源码未改，测试就必然相同”。 |
| 浏览器交互 | tab、会话、DOM 控件、已填表单、导航与提交等动作的效果。 | 交互状态与操作副作用；可见页面只是环境状态的一部分。 | “Web 都不可恢复”或“同 URL / 同观察即可安全跳过点击或提交”。 |
| 检索文档与引用 | 语料可达性、文档/视图片段、cursor 与引用行号的对应。 | 定位、表示和证据依赖；可把相同正文与不同引用标识分别管理。 | “有 URL 就能重取全文”“得到短答案就已保留全部证据”。 |

这些是**对象与操作类型的专用规则**，不宜视作某个 agent 身份独占的 property。同一 agent 可以跨多类对象，同一对象也可通过不同表示和工具被访问。

“稳定窗口较长”“重取代价较高”“引用更精确”也可以作为统一模型的参数。当前材料**没有测出数据库查询代价高，也没有给出数据库短期更新频率**，只能说这些 DAB 轨迹未观察到写库动作。读多写少、快照可确认、查询昂贵应作为后续受限场景的假设，而不是当前样本已证明的共性或 Data Agent 专有特征。

## 4. FreeInference 补充的是 context 层面的共性

- [F1 请求 9→11](../samples/freeinference/01-append/README.md#request-9)：大工具结果进入后，下一请求继续携带长工具历史；能说明输入重复，不能识别语义用途。
- [F2 请求 24→25](../samples/freeinference/02-injection/README.md#request-24)：输入净增 87 token，共享前缀降为 65.59%。这是输入改写的证据，没有外部对象更新证据。
- [F3 请求 21→23](../samples/freeinference/03-dropped-turns/README.md#request-21)：裁剪历史后前缀大幅缩短，下一轮又可复用新的前缀。改变的是 context 的内容与组织；没有证据说明数据源或任务对象随之改变。

因此，缓存保持和 context 重写代价可以作为共同的系统层问题；其收益仍受 token 规模、请求间隔和服务端缓存规则影响。它与外部观察的语义有效性应分别建模，不能把缓存命中、文本相同或内容重复等同于可安全删除。

## 5. 对研究定位的修订

建议将研究主张改为：

> 不同应用可以共享“状态是否匹配、后续是否依赖、恢复是否成立”这一组 context 管理问题。对象的结构、可变性及访问方式，结合任务、工具操作与 agent 的历史管理方式，共同影响这些条件的检查方法及优化收益。Data Agent 可以作为首先研究的受限实例：尝试利用已物化结果、结构化计算和数据依赖，给出可检查的复用与缩减规则；迁移到 Coding、Web 或检索问答时，保留共同模型，替换类型相关的状态和依赖检查。

实际可考虑的统一动作包括保留原观察、保留局部证据或派生产物、保留可恢复引用、刷新失效观察；**当前样本只支持这些决策问题具有共性，没有证明某套统一策略已安全有效**。未知依赖、未知版本和不可验证恢复应保留为未知，不能由应用标签代替判断。

证据边界：显式引用不等于完整依赖；可见状态不等于完整环境；局部产物不自动是充分统计量；有恢复入口不保证相同内容或低成本。S2 的来源 `resolved=0`、Q3 的 final 与顶层 answer 不一致，也提醒我们不能把工具执行成功当作这些条件已满足。
